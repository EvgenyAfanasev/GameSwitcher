# GameSwitcher — дизайн-спецификация

Дата: 2026-11-21
Статус: утверждено в ходе брейншторма (мокапы: `.superpowers/brainstorm/`)

## 1. Цель

Desktop-приложение для Windows (портативные консоли, тач-управление), которое хранит снапшоты настроек графики игр и применяет их перед запуском. Один глобальный переключатель («режим») меняет настройки всех игр сразу; отдельная игра может быть привязана к своему конкретному профилю.

Сценарий использования: настроил графику в игре → вышел → сохранил профиль в GameSwitcher. Дома — активен режим `Performance`, в поездке — один тап на `Eco`.

Технологии: **Electrobun 2.x** (проверено: v2.0.5, Windows x64/ARM64, системный рендерер WebView2, сборка через `hutch`). UI — минимальный vanilla TypeScript, без фреймворков.

## 2. Решения, принятые в брейншторме

| Вопрос | Решение |
|---|---|
| Определение мест настроек | Ручное указание целей снапшота + подсказки типичных путей (сканер кандидатов) |
| Модель запуска | GameSwitcher — лаунчер: применяет профиль ДО запуска игры |
| Типы игр | Любой `.exe`; опционально Steam AppID → запуск через `steam://rungameid` |
| TDP | Вне скоупа (только настройки графики) |
| Главный экран | Список строк (не сетка) |
| Приватные профили | Профиль игры может быть частным (виден только в игре) или связанным с глобальным режимом |
| Режимы | Сколько угодно, Eco/Performance — только стартовые примеры |

## 3. Терминология

- **Режим (mode)** — глобальный профиль-«слот»: `Eco`, `Performance`, … Активен ровно один.
- **Игра (game)** — exe + метаданные + цели снапшота + профили.
- **Профиль игры (profile)** — снапшот настроек этой игры. Два вида:
  - **связанный** — привязан к режиму (`modeId`), управляется глобальным переключателем;
  - **частный** — `modeId = null`, виден только в этой игре, глобально не переключается.
- **Цель снапшота (configTarget)** — файл / папка / ветка реестра, которые снимает профиль.
- **Override** — фиксация игры на конкретном профиле (частном или связанном), в обход глобального режима.

## 4. Модель данных

Хранилище: `%APPDATA%\GameSwitcher\`
- `store.json` — манифест (версия схемы, настройки, режимы, игры, профили);
- `snapshots/<profileId>/` — файлы снапшотов и `.reg`-дампы;
- `icons/<gameId>.png` — иконки игр.

```jsonc
{
  "version": 1,
  "settings": { "autostart": false },
  "activeModeId": "m1",
  "modes": [
    { "id": "m1", "name": "Eco", "color": "#3fb950", "createdAt": 1732160000000 }
  ],
  "games": [
    {
      "id": "g1",
      "name": "ELDEN RING",
      "exePath": "D:\\Games\\ELDEN RING\\eldenring.exe",
      "steamAppId": null,
      "iconPath": null,
      "overrideProfileId": null,
      "configTargets": [
        { "type": "file", "path": "C:\\Users\\You\\Documents\\My Games\\ELDEN RING\\Graphics.xml" },
        { "type": "folder", "path": "C:\\Users\\You\\Documents\\My Games\\ELDEN RING\\Saved\\Config" },
        { "type": "registry", "key": "HKCU\\Software\\FromSoftware\\EldenRing" }
      ],
      "profiles": [
        {
          "id": "p1",
          "name": "Eco",
          "modeId": "m1",
          "createdAt": 1732160000000,
          "snapshot": {
            "files": [ { "targetIndex": 0, "relPath": "0/Graphics.xml", "size": 2048, "hash": "sha256..." } ],
            "registry": [ { "targetIndex": 2, "file": "registry/0.reg" } ],
            "totalSize": 2048
          }
        }
      ]
    }
  ]
}
```

Инварианты:
- у игры **не более одного связанного профиля на режим** (слот занят → повторное сохранение предлагает ↻ перезапись с подтверждением);
- имена частных профилей уникальны внутри игры;
- `overrideProfileId` ссылается только на существующие профили; при удалении профиля — обнуляется;
- при удалении режима все его связанные профили становятся **частными** (`modeId = null`, имя сохраняется); если активный режим удалён — активным становится первый оставшийся, при нуле режимов — пустое состояние с приглашением создать режим;
- удаление игры удаляет её профили и снапшоты (с подтверждением).

## 5. Правило эффективного профиля

```
resolveEffectiveProfile(game):
1. game.overrideProfileId != null → этот профиль
2. иначе → профиль игры с modeId == активный режим
3. иначе → null (запуск без изменений, бейдж «—»)
```

Единая чистая функция, покрытая юнит-тестами.

## 6. Снапшоты

### 6.1 Файлы

- Снапшот цели `file` — копия файла; цели `folder` — рекурсивная копия дерева.
- Применение: копирование файлов поверх текущих (недостающие каталоги создаются). **Лишние файлы не удаляются**, значения вне снапшота не трогаются.
- Файл-цель отсутствует при снапшоте → пропускается (игра могла ещё не создать конфиг); отсутствует при применении → восстанавливается из снапшота.
- В манифесте: размер и sha256 каждого файла.

### 6.2 Реестр

- Снапшот цели `registry` → `reg export HKCU\... snapshots/<id>/registry/<i>.reg`.
- Применение → `reg import <файл>`.
- Без нативных модулей — только штатный `reg.exe`.

### 6.3 Защита от ошибок

- Экран сохранения показывает объём: «снимем: N файлов + M значений реестра, X КБ».
- Суммарный объём целей > 50 МБ → предупреждение перед сохранением.
- Цели > 200 МБ отклоняются при выборе с объяснением (случайно отмечена папка данных/сейвов).
- Папки-исключения сканера: `saves`, `savegames`, `save`, `SaveGames`, `Saved/SaveGames` — **сейвы никогда не предлагаются** (восстановление старого сейва — порча прогресса).

### 6.4 Применение перед запуском

- Применение профиля выполняется **только при запуске игры** из приложения (отдельного действия «применить без запуска» нет: игра всё равно перезапишет конфиг своим состоянием при выходе).
- Проверка: exe игры не запущен (`tasklist /FI "IMAGENAME eq ..."`) → если запущен, запуск блокируется с сообщением (применять профиль в работающую игру бессмысленно — игра перезапишет конфиг при выходе).
- Ошибка применения → игра **не запускается**, показывается ошибка + «Повторить».

## 7. Сканер путей (кандидаты целей)

При добавлении игры по exe:
1. Извлекаем productName (version resource, через PowerShell) — fallback: имя exe.
2. Кандидаты (case-insensitive совпадение по productName / имени папки exe):
   - `%USERPROFILE%\Documents\My Games\<совпадение>\` — для Unreal-стиля предлагается узко `...\Saved\Config`, не весь корень;
   - `%LOCALAPPDATA%\<совпадение>\`, `%APPDATA%\<совпадение>\` — с пометкой «кэш, обычно не нужен»;
   - верхний уровень папки exe: файлы `*.ini|*.xml|*.json|*.cfg|*.toml` (< 10 МБ) и каталоги `config|settings`;
   - `HKCU\Software\<совпадение>` — с подсчётом значений (`reg query`).
3. Кандидаты с галочками; ничего не нашлось → ручное добавление: файл / папка / ветка реестра (текстовый ввод с валидацией `HKCU\...`).

Иконка и имя: PowerShell `ExtractAssociatedIcon` → PNG 64×64; не удалось → цветная плитка-генератор с первой буквой.

## 8. Запуск игр

- Прямой: spawn exe, cwd = папка exe, detached.
- Steam (`steamAppId` задан): `cmd /c start "" "steam://rungameid/<id>"` — работают оверлей, достижения, часы Steam.
- После запуска окно GameSwitcher сворачивается.
- Launch-аргументы exe — вне скоупа v1.

**Steam Cloud:** если игра синхронизирует настройки через облако, оно может перезаписать применённый профиль. Приложение на этапе добавления Steam-игры показывает подсказку «отключи Steam Cloud для этой игры в настройках Steam». Автоматическое вмешательство в internals Steam — вне скоупа (хрупко).

## 9. UI

Стиль: тёмный (`#16181c`), ультра-минималистичный, тач-размеры ≥ 44 px, строки 64 px, модальные действия — bottom sheets. Язык интерфейса — русский (строки в одном модуле, задел под i18n). Окно открывается развёрнутым, рамка стандартная Windows. Режимы имеют автоназначаемые акцентные цвета (палитра по порядку создания).

### 9.1 Главный экран
- Шапка: название, пилюли режимов (активный — залит цветом), «+» (новый режим), «⚙».
- Строки игр (64 px): иконка, название, подпись («запуск через Steam» / «нет профиля <режим> — запуск как есть»), бейдж эффективного профиля (цвет режима; у override — маркер ⚡; нет профиля — контурный «—»), «⋯».
- Тап по строке → запуск. Тап по «⋯» → bottom sheet: **Запустить / Сохранить текущие настройки как профиль / Профили и настройки игры**.

### 9.2 Экран игры
- Кнопка «▶ Запустить · <профиль>» (эффективный профиль крупно).
- Переключатель override: `[Глобальный] [Eco] [Performance] … [частные профили]`; «Глобальный» = следовать глобальному (отвязать).
- «Сохранить текущие настройки как профиль»: выбор «в глобальный (слот)» или «частный (имя)».
- Список профилей: цвет режима, имя, объём, дата; ↻ (обновить снапшот из текущего состояния, с подтверждением), 🗑 (удалить, с подтверждением).
- Цели снапшота: краткий список + «изменить».
- Steam AppID и цели — редактируемые.

### 9.3 Добавление игры
Шаг 1: exe (Обзор) → имя/иконка из exe → Steam AppID (опц.). Шаг 2: чекбоксы найденных целей (сканер) с размерами + ручное добавление.

### 9.4 Сохранение профиля (bottom sheet)
«Снимем: N файлов + M значений, X КБ» → ветка «в глобальный [пилюли режимов] [+ новый]» / «частный [имя]» → Сохранить.

### 9.5 Настройки
- Режимы: создать / переименовать / удалить (удаление — с предупреждением о судьбе связанных профилей).
- Автозапуск с Windows: реестр `HKCU\...\CurrentVersion\Run`.

## 10. Архитектура

```
┌─ Renderer (WebView2, vanilla TS) ─ только UI, без fs
│        │ electrobun view.rpc
┌─ Main-процесс (Electrobun runtime) ─ вся логика:
   ├── store        — чтение/запись store.json, миграции по "version"
   ├── modes        — CRUD режимов, активный режим
   ├── games        — CRUD игр, целей, профилей
   ├── scanner      — кандидаты целей (чистая функция над fs)
   ├── snapshot     — снятие/применение снапшотов (файлы + reg.exe)
   ├── launcher     — проверка процесса, apply, spawn, эффективный профиль
   └── autostart    — реестр Run-ключа
```

Модули main-процесса — **чистые TS-модули без зависимости от Electrobun API** (fs/child_process через узкий адаптер): юнит-тесты идут на любой ОС, и при проблемах в раннем Electrobun 2 shell заменяется с минимальными потерями.

## 11. Обработка ошибок (сводно)

| Ситуация | Поведение |
|---|---|
| Игра запущена при запуске из приложения | Блок: «Игра уже запущена» |
| Ошибка применения профиля | Игра не запускается; ошибка + «Повторить» |
| Файл-цель отсутствует при снапшоте | Пропуск, отмечается в манифесте |
| Файла нет на диске, но есть в снапшоте | Восстанавливается из снапшота |
| Снапшот > 50 МБ | Предупреждение до сохранения |
| Цель > 200 МБ | Отклоняется при выборе |
| WebView2 отсутствует | Electrobun сообщает сам; в README — ссылка на установку Evergreen Runtime |

## 12. Тестирование

- **Юниты (кросс-платформенно, Linux dev):** resolveEffectiveProfile, store CRUD/миграции, snapshot-файлы (копия/восстановление на tmpfs-фикстурах), сканер (fake fs), валидация инвариантов (слот на режим, override-ссылки).
- **Windows-only (вручную на приставке/ПК):** reg export/import, tasklist-проверка, steam:// запуск, иконки, автозапуск.
- **CI (GitHub Actions, windows-latest):** `hutch electrobun build` + smoke-запуск. hutch не кросс-компилит — сборка только на нативном раннере.

## 13. Риски

1. **Electrobun 2.0.5 на Windows молод** — возможны баги RPC/спавна. Митигируется чистыми модулями (п. 10).
2. **WebView2 Runtime** может отсутствовать на «голой» Windows — документируем установку.
3. **Steam Cloud** может перезаписать профиль — только подсказка (п. 8).
4. Нестандартные игры хранят настройки в неожиданных местах — закрывается ручным добавлением целей.

## 14. Этапы реализации

1. **Core:** store + инварианты + resolveEffectiveProfile + snapshot-движок (юнит-тесты).
2. **Shell:** Electrobun-каркас, главный экран, режимы CRUD.
3. **Добавление игры:** сканер, иконки, Steam AppID, ручные цели.
4. **Экран игры:** сохранение профилей, override, список профилей.
5. **Launcher:** применение + запуск + обработка ошибок.
6. **Полировка:** настройки/автозапуск, пустые состояния, проверка на Windows-устройстве.

## 15. Вне скоупа (v1)

TDP-управление, трей, launch-аргументы exe, i18n (кроме русского), автоматическое отключение Steam Cloud, массовость/автоопределение целей без участия пользователя.
